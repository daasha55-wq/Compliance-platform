# CaseDetail

**Размер:** desktop 1440×1024
**Назначение:** карточка кейса с прогрессивным раскрытием: сводка сразу → детали по клику → решение по риск-тиру → запись в аудит-лог (PRD, раздел 6, user stories 1, 2, 9, 10, 11, 12)

## Секции (сверху вниз)

### Header (64px высота)
- Logo (левый край)
- Хлебная крошка: «Очередь кейсов / Кейс #4821 — Ксения Воробьёва»
- Avatar + меню профиля (правый край)

### Sidebar (240px ширина, слева)
- Case Queue
- Account Settings

### CaseSummaryBar (под header, во всю ширину main-области, 120px высота)
- Риск-тир: крупная иконка формы (▲) + подпись «High risk»
- Статус кейса: текстовый бейдж «Ожидает решения»
- Identity-блок: имя «Ксения Воробьёва», дата рождения «14.03.1991», страна «Кипр», статус верификации документа «Подтверждён (Sumsub)»
- DiscrepancyBanner: если источники расходятся — заметная строка «⚠ Sumsub и ComplyAdvantage расходятся» с текстовой подписью, не только цветом (см. user story 11)

### ExplainabilitySummary (сразу под CaseSummaryBar, видна без разворачивания секций)
- Версия модели: «risk-model v2.3»
- Ключевые сработавшие правила (3-4 пункта): «PEP-совпадение 82% схожести», «Страна повышенного риска: Кипр», «Возраст аккаунта отправителя < 30 дней»
- Подпись: «Полный список правил — в разделе ниже»

### ProgressiveDisclosure (аккордеон, все секции свёрнуты по умолчанию)

#### AML/Sanctions/PEP screening (по клику разворачивается)
Три отдельных статуса, не агрегированный скор (см. user story 2):
- Санкционные списки: «Совпадений нет»
- PEP: «Совпадение найдено» + иконка + подпись «82% схожести — Воробьёва К. И., публичное лицо, список OFAC»
- Adverse media: «1 упоминание найдено»
Клик по совпадению → разворачивает деталь (какой список, степень схожести)

#### Документы (по клику разворачивается)
- Превью-плейсхолдеры документов (паспорт, селфи-верификация) 160×120
- Подпись под каждым: «Паспорт.pdf», «Селфи-верификация.jpg»

#### CaseHistory — вкладка аудит-лога (по клику разворачивается или отдельная вкладка вверху секции)
Read-only список записей, сверху вниз (новые сверху):
- «25.08.2026, 14:02 — Кейс создан системой, входные данные получены от Sumsub/ComplyAdvantage»
- «25.08.2026, 14:03 — Риск-тир присвоен: High, правило risk-model v2.3»
- «25.08.2026, 14:10 — Открыт компаенс-офицером Анной Смирновой»
Каждая запись: timestamp, автор («система» или имя), действие, версия модели/входные данные, если применимо (см. user story 12)

#### Полный список сработавших правил (по клику разворачивается)
Таблица: правило / вес / сработало (да/нет) — плейсхолдер на 6-8 строк

### DecisionPanel (нижняя часть main-области, всегда видна, не требует скролла до конца)
Состояние зависит от риск-тира:
- **High** (текущий пример): кнопка «Подтвердить решение» неактивна, пока ExplainabilitySummary не была видна на экране (см. user story 6); рядом кнопка «Эскалировать на подтверждение» (переводит в статус «Ожидает подтверждения», см. user story 7); кнопка «Отклонить»
- **Medium**: те же кнопки + видимый остаток SLA рядом с кнопками
- **Low**: панель заменена на информационную строку «Кейс одобрен автоматически 25.08.2026 в 14:03 по правилу risk-model v2.3» без кнопок действия (см. user story 4)

## Состояние ошибки (ErrorState)
Если Sumsub или ComplyAdvantage недоступны при загрузке кейса — CaseSummaryBar и соответствующая часть ProgressiveDisclosure заменяются на явный блок: иконка предупреждения + «Sumsub временно недоступен» + подпись «Данные обновятся автоматически при восстановлении соединения» (см. user story 1, AC про явное состояние ошибки вместо пустого поля).
