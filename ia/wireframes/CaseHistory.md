# CaseHistory

**Размер:** desktop 1440×1024
**Назначение:** read-only вкладка аудит-лога карточки кейса, вынесенная в отдельный экран для сценария case-review (см. `ia/flows/case-review.mmd`) — кто/когда/что сделал с кейсом, версия модели и входные данные там, где применимо (PRD, раздел 10: «CaseHistory — read-only вкладка аудит-лога внутри карточки кейса»; user story 12)

## Секции (сверху вниз)

### Header (64px высота) — идентично CaseDetail
- Logo (левый край)
- Хлебная крошка: «Очередь кейсов / Кейс #4821 — Ксения Воробьёва / История»
- Avatar + меню профиля (правый край)

### Sidebar (240px ширина, слева) — идентично CaseQueue/CaseDetail
- Case Queue
- Account Settings

### TabBar (под header, во всю ширину main-области)
- Вкладка «Сводка» (ведёт обратно в CaseDetail)
- Вкладка «История» (активна на этом экране)

### HistoryList (основная область, read-only)
Список записей, сверху вниз, новые сверху. Каждая запись: timestamp, автор («система» или имя), действие, версия модели/входные данные — если применимо (см. user story 12):

- «24.08.2026, 14:31 — Ожидает решения Senior Compliance Officer»
- «24.08.2026, 10:15 — Эскалирован на подтверждение Анной Смирновой: «Не согласна с авто-скором, PEP-совпадение требует второго мнения»»
- «24.08.2026, 10:02 — Открыт компаенс-офицером Анной Смирновой»
- «24.08.2026, 09:20 — Обнаружено расхождение источников: дата рождения (Sumsub 14.03.1989 vs ComplyAdvantage 14.03.1988)»
- «24.08.2026, 09:15 — Риск-тир присвоен: High, правило risk-model v2.3»
- «24.08.2026, 09:14 — Кейс создан системой, входные данные получены от Sumsub/ComplyAdvantage»

## Состояние пустого списка
Не предусмотрено осознанно: минимум одна запись («Кейс создан системой») существует всегда с момента появления кейса — полностью пустой HistoryList невозможен по построению.
