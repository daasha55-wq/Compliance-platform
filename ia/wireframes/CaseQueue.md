# CaseQueue

**Размер:** desktop 1440×1024
**Назначение:** Compliance Officer видит очередь кейсов, требующих внимания, и приоритизирует работу по риск-тиру и SLA (PRD, раздел 6, user story 3, 5, 8)

## Секции (сверху вниз)

### Header (64px высота)
- Logo (левый край)
- Заголовок раздела: «Очередь кейсов»
- Avatar + меню профиля (правый край)

### Sidebar (240px ширина, слева)
- Case Queue (active)
- Account Settings

### FilterBar (48px высота, под header, над таблицей)
- Сегмент-контрол по риск-тиру: Все / Low / Medium / High
- Дропдаун по статусу: Новый / На проверке / Ожидает подтверждения / Одобрено / Отклонено
- Сортировка: по SLA / по дате создания
- Счётчик справа: «24 кейса в очереди»

### CaseTable (основной контент, растягивается по высоте)
Колонки слева направо:
- **Риск-тир** — иконка формы + текстовая подпись (треугольник = High, ромб = Medium, круг = Low — тир обозначен формой, не только цветом, см. PRD user story 3 и 13)
- **Заявитель** — имя
- **Статус** — текстовый бейдж (не цветом)
- **SLA** — оставшееся время для Medium-кейсов («18ч 32м») или пометка «Просрочено» (только для Medium, см. user story 5)
- **Дата создания**
- **Расхождение источников** — иконка предупреждения + подпись, если Sumsub и ComplyAdvantage разошлись (см. user story 11); пусто, если расхождения нет

## Пустое состояние (EmptyCaseQueue)
Если кейсов нет — по центру таблицы: большая иллюстрация-плейсхолдер + H2 «Очередь пуста» + подпись «Новые кейсы появятся здесь по мере поступления заявок». Без CTA — очередь наполняется системой, а не действием пользователя.

## Состояние загрузки (LoadingState)
Header, sidebar и FilterBar отображаются как обычно. На месте CaseTable — 6 серых полос-скелетонов вместо строк.
