# UX-паттерны конкурентов

Обновлено с учётом `deep_research_results.md`.

## 1. Отраслевой стандарт — что делают все одинаково (ожидания пользователей)

- **No-code visual workflow/rule builder** — Sumsub Workflow Builder, Persona Flow Editor, Alloy decision engine, Unit21 no-code rules, настраиваемый risk scoring у ComplyAdvantage. Все пять дают настройку правил верификации/риска без разработчика. Отсутствие этого будет считаться регрессом, не нейтральным решением — это базовое ожидание compliance-офицера от 2026 года.
- **Централизованный кейс-менеджмент с аудит-трейлом** — присутствует у всех пяти в каком-то виде (у ComplyAdvantage и Persona — с оговорками по глубине).
- **Sanctions/PEP/adverse media screening как непрерывный (не разовый) процесс** — ongoing/perpetual monitoring, а не проверка только на входе, стандарт у всех пяти (глубина заявлена по-разному, см. `competitor_features.md`). Deep research подтверждает, что это не просто конкурентная норма, а отраслевой тренд perpetual KYC (Fenergo, Capgemini, SymphonyAI) и требование FATF Rec.10/AMLR — наш периодический re-review из брифа нужно дополнить событийным мониторингом, иначе продукт будет восприниматься как отстающий от рынка, а не просто «другой».
- **Программа сниженного входа для ранних стартапов** — Sumsub (self-serve триал), ComplyAdvantage (ComplyLaunch, бесплатно), Persona (free tier + Startup Program). 3 из 5 явно инвестируют в снижение барьера первой пробы — это уже почти стандарт сегмента, не исключение.
- **Risk scoring на базе ML/AI как основа решения** — универсально у всех пяти, различается только степень объяснимости (см. точки расхождения).
- **Enterprise-тир с ценой "по запросу" как потолок** — у всех пяти есть верхний уровень с непубличной ценой.

## 2. Точки расхождения — где решают одну задачу по-разному

| Задача | Вариант A | Вариант B |
|---|---|---|
| GTM / вход в продукт | Self-serve + публичная цена (Sumsub, ComplyAdvantage Starter, Persona) | Полностью sales-led без публичной цены (Alloy, Unit21) |
| Объяснение AI-вердикта | Число/скор без развёрнутого объяснения (Sumsub, Alloy) | AI-нарратив человеческим языком (Unit21, отчасти ComplyAdvantage как regulatory-заявление) |
| Human review gate | Скрыт внутри threshold-настроек no-code rules (большинство) | Явный guardrail-флаг "нужен review" на уровне паттерна (Unit21 — единственный) |
| Модель источников данных | Собственное ядро + точечные партнёрства (Sumsub, Persona, ComplyAdvantage) | Чистая multi-vendor оркестрация без своего data engine (Alloy) |
| Глубина кейс-менеджмента | Полноценный investigation workflow (Unit21, Alloy, Sumsub) | Признанно недостаточный для масштаба (ComplyAdvantage) или доступен только на старших тарифах (Persona Advanced Cases) |
| Заявленная vs реальная доля авто-одобрений (STP) | Маркетинговые заявления вендоров категории — 70–85% | Независимые бенчмарки (McKinsey, Acquaintsoft/PwC) — реалистичный диапазон для физлиц 35–55%, гибридные модели стартуют с manual review ~45% и снижаются до ~25% после года тюнинга |
| Прозрачность override rate | Публичного индустриального бенчмарка не существует ни у одного из пяти | Открытая ниша — есть определение KPI (Galileo AI) и таргет «<10% необъяснённых override», но никто в категории его не публикует |

## 3. Рекомендации — какой паттерн взять, у кого и почему

**Взять:**
- **У Persona** — self-serve онбординг без обязательного демо + щедрый free/Startup-tier. Прямое попадание в нашу аудиторию (растущие, не enterprise, стартапы); снижает барьер первой пробы продукта до нуля.
- **У Sumsub / Persona** — no-code visual workflow builder. Это отраслевой стандарт (см. п.1); его отсутствие будет читаться как недоделанность продукта, а не как осознанное решение.
- **У Unit21** — паттерн "AI формулирует нарратив решения человеческим языком + явный флаг, когда нужен human review". Адаптировать под наш 4-eyes: у Unit21 это безролевой guardrail, у нас — отдельная роль Senior Compliance Officer и отдельный статус кейса, чего нет ни у одного конкурента.
- **У ComplyAdvantage** — программа бесплатного/дешёвого входа для самых ранних стартапов (аналог ComplyLaunch). Канал привлечения нижней границы нашей аудитории, пока она не доросла до "полноценного" клиента.
- **Из отраслевых данных usage-based SaaS в целом (не из наших 5 конкурентов — источник: Culta/Stripe/Zylo через deep_research_results.md)** — real-time дашборд использования с алертами на 50/75/90% ожидаемого потребления и опциональные hard caps. 78% IT-лидеров сталкивались с bill shock от consumption-моделей; без этого паттерна наша модель seats+usage overage рискует повышенным оттоком несмотря на в целом более высокий NRR usage-based подхода. Это не паттерн, который можно "взять у конкурента" — ни один из пяти его не показывает явно, — а превентивная мера, обязательная для нашей ценовой модели.
- **Публикация override rate как метрики** — раз индустриального бенчмарка не существует ни у одного конкурента (см. таблицу выше), мы можем сделать это частью публичного позиционирования продукта, а не только внутренним OKR — задаёт категорию, а не догоняет её.

**Не повторять:**
- **У Alloy и Unit21** — полностью закрытая sales-led модель без единой точки публичной цены. Прямо противоречит нашей ценностной позиции доступности для растущих стартапов (см. brief.md, п.1 — ключевой дизайн-вызов).
- **У ComplyAdvantage** — резкий функциональный обрыв между Starter и Enterprise (transaction monitoring доступен только в Enterprise). Создаёт "ловушку роста" — ровно то, чего наша модель ценообразования (seats + usage overage, без отдельного тира) должна избежать.
- **У Persona** — путаная терминология в UI (inquiry vs verification). Простое, но показательное напоминание: term consistency в карточке кейса и статусах — не мелочь, пользователи явно жалуются на это в отзывах.
- **Маркетинговые заявления о STP 70–85%** — независимые бенчмарки дают 35–55% для физлиц; закладывать в продукт и в коммуникацию с клиентами реалистичный диапазон, иначе завышенные ожидания по авто-одобрению обернутся разочарованием при масштабировании клиента.
