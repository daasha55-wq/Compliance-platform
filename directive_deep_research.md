# Директива: Глубокое исследование через /deep-research (deep_research)

> **Запуск:** только когда пользователь явно дал эту директиву. Переиспользуемая. Всё внутри Claude Code — наружу (Gemini DR, Perplexity, экспорт .docx) не выходим.

## Задача
Провести глубокое исследование рынка и конкурентов по проекту силами встроенного в Claude Code `/deep-research`, не выходя из среды. Результат — отчёт со ссылками, сохранённый в проект, готовый для следующего шага (конкурентный анализ).

`/deep-research` можно вызвать и вручную, описав задачу своими словами. Эта директива делает то же самое точнее: подхватывает контекст проекта (бриф и, если есть, поверхностный ресёрч `competitive_analysis.md`) и формирует вопросы ровно под продукт, не дублируя уже собранное.

## Предусловие
- В проекте есть `brief.md` и, желательно, результат быстрого ресёрча `competitive_analysis.md`.
- В Claude Code включён веб-поиск / Research. Если `/deep-research` недоступен — останови и попроси пользователя проверить, что на его плане включён веб-поиск.

## Инструкция
1. Прочитай `brief.md` и `competitive_analysis.md` (если есть). Пойми продукт, аудиторию, нишу и что уже выяснено на быстром шаге.
2. Сформулируй пул до 7 глубоких исследовательских вопросов, которые вытекают из брифа и **не дублируют** быстрый ресёрч. Направления:
   - объём и динамика рынка в нише, темпы роста;
   - тренды в категории продукта;
   - повторяющиеся жалобы пользователей в отзывах / на форумах;
   - самые запрашиваемые фичи;
   - ценовые модели и их эффективность;
   - слабые места конкурентов по данным за длительный период.
3. **Спроси у пользователя глубину под его план/лимиты — до запуска.** `/deep-research` жрёт лимиты в разы больше обычного прогона, глубина = число вопросов (отдельного ползунка нет). Покажи пул и предложи: тесные лимиты → 3 главных вопроса; есть запас (план Max) → до 7. Не запускай веер, который может не докрутиться и слить недельный лимит впустую.
4. Запусти по **выбранному** набору встроенный deep research — в Claude Code это команда `/deep-research` с вопросами, привязанными к брифу. Он веером ищет по многим источникам, перекрёстно проверяет факты и собирает отчёт со ссылками.
5. Дождись отчёта и сохрани его в файл `deep_research_results.md` в корне проекта, со ссылками на источники.

## Формат результата
`deep_research_results.md`: структурированный отчёт (рынок / тренды / пользователи / конкуренты) + список источников. Готов к использованию в директиве конкурентного анализа на следующем шаге.

## Важно
- Вопросы привязаны к нашему проекту, не общие.
- Не дублируй `competitive_analysis.md` — копай глубже, туда, куда быстрый ресёрч не дошёл (статистика, динамика, длинный период).
- Отчёт остаётся в проекте, чтобы следующий шаг подхватил его без копипаста.

## Грабли
- **Веб-поиск выключен** → `/deep-research` не отработает. Проверь, что на плане Claude включён веб-поиск / Research.
- **Жрёт лимиты в разы.** Веер параллельных агентов = кратный расход против обычного прогона. Не сливай недельный лимит на один прогон: при тесных лимитах бери 3 вопроса, не запускай веер, который не докрутится.
- **Глубина ≠ бесконечность:** deep research идёт заметно шире быстрого ресёрча и перекрёстно проверяет, но это не отменяет ручную сверку критичных цифр — ключевые числа проверь по ссылкам из отчёта.
